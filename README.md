# Cafe Share（カフェシェア）

## 概要

**Cafe Share** は、お気に入りのカフェ情報を登録・共有できるWebサービスです。

カフェの情報を投稿し、メニューやレビューを通じてユーザー同士でカフェ体験をシェアできます。

---

## 作成背景

「このカフェ、雰囲気よかったのに名前忘れた…」「友達におすすめのカフェを教えたい」
そんな経験から、カフェ情報をストックして気軽にシェアできるサービスを作りたいと思い開発しました。

---

## 機能一覧

- **ユーザー登録 / ログイン** （Laravel Breeze / メール認証対応）
- **カフェ投稿** （店名・住所・営業時間・電話番号・説明・メイン画像）
- **カフェ編集 / 削除** （投稿者本人のみ操作可能）
- **サブ画像アップロード** （複数枚の写真を登録可能）
- **Google マップ表示** （カフェ詳細画面に地図を埋め込み）
- **メニュー管理** （メニュー名・価格・説明・画像の登録・削除）
- **レビュー投稿** （星評価 1〜5 ＋ コメント）
- **カフェ一覧** （平均評価・レビュー件数・スター表示付き）

## 工夫した点

### Dockerを使った開発環境の構築

Dockerは、現在の開発現場では基本的な技術であると考え挑戦しました。開発者ごとの環境差異による問題を抑えて、同一環境で開発・動作確認ができる便利さと、設定ファイルの構築の難しさを痛感しました。

### Vue3を使ったモダンな開発に挑戦

今回、ポートフォリオを作成する上で、バックエンドだけでなくフロントエンドのフレームワークを使うことに挑戦しました。Vue3のComposition APIを活用し、可読性や保守性を意識した実装を行いました。フォームの処理にはuseFormを利用し、とても簡潔なコードで実装することができました。既存のコンポーネントを利用することで、可読性のある統一感のあるコードがかけることを学びました。

### フォームリクエストを使ったバリデーション

バリデーションルールを専用クラスで管理することでコントローラーの責務を減らし、コードの可読性や保守性を高ました。

### ポリシーを使った認可

投稿者本人のみでしか使えない機能（カフェの編集・削除・メニュー操作）に対して、Laravelのポリシークラスを利用した認可を実装しました。コントローラーに直接記述することを避け、責務を分離しつつ、再利用性を高めました。

### 画像の保存と表示

カフェのメイン画像、サブ画像、メニューの画像といった、使用用途が違う３種の画像を、機能要件に合うように保存・表示を行いました。

### Google Maps連携

カフェの住所をもとにiframe埋め込みで地図を自動表示しました。

### モーダルを使った画面遷移を必要としない入力

メニューの追加機能の際、メニュー追加ページへ遷移するのはユーザー体験が悪いと感じたため、モーダルを使って画面遷移なく行えるように実装しました。また、モーダルはHeadless UIというCSSフレームワークのDialogコンポーネントを再利用して実装するなど、使いやすさと実装のしやすさを意識した開発をしました。

### Certbotを利用したHTTPS化

EC2にCertbotをインストールしHTTPS化を行いました。Certbotは無料の証明書を発行してくれるサービスで、コストをかけずにHTTPS化を実現しました。
